# Contributing

These are the defaults for `philoserf` repositories. A repository with its own
`CONTRIBUTING.md` overrides this one.

## Issues

Search the existing issues first. For a bug, say what you expected, what
happened instead, and which versions you are running. For a security
vulnerability, follow the
[security policy](https://github.com/philoserf/.github/blob/main/SECURITY.md)
instead of opening an issue.

## Pull requests

- One concern per pull request.
- Match the surrounding style, and run whatever lint, format, and test commands
  the repository defines before pushing.
- Write [Conventional Commits](https://www.conventionalcommits.org/) subjects:
  `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`.
- Describe why in the pull request; the diff already shows what.
